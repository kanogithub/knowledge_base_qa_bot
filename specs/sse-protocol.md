# Cloud-KB — SSE Line Protocol Specification

Server-Sent Events (SSE) standardizes a text-based, one-way push protocol over HTTP. This document specifies the exact wire format for both the **Long-Lived Notification Channel** and the **Short-Lived Chat Response Channel**.

---

## 1. Global Wire Format Rules

All SSE responses in the system MUST adhere to the W3C recommendation:
- **Headers:** The server response MUST contain these headers:
  ```http
  Content-Type: text/event-stream; charset=utf-8
  Cache-Control: no-cache
  Connection: keep-alive
  ```
- **Encoding:** UTF-8 encoded text.
- **Line Endings:** Lines are separated by a single Line Feed character (`\n`) or Carriage Return + Line Feed (`\r\n`).
- **Data Frames:** Each frame consists of one or more lines starting with a field name, followed by a colon (`:`), followed by the field value.
- **Frame Endings:** A data frame is terminated by **two consecutive line endings** (`\n\n`).

---

## 2. Notification Channel (GET /api/notifications/stream)

### Channel Lifecycle
- **Establishment:** Triggered by the client connection.
- **Heartbeat:** To prevent intermediate proxies or firewalls from dropping idle connections, the service MUST send a **keep-alive ping comment** every **30 seconds**.
- **Heartbeat format:**
  ```text
  :ping\n\n
  ```
  *(A line starting with a colon is a comment in SSE and is ignored by standard client parsers, but keeps the TCP connection active).*

### Event Types & Payloads

#### Event Type A: `IndexProcessing`
- **Trigger:** Worker starts processing Markdown compilation.
- **Payload format:**
  ```text
  event: IndexProcessing
  data: {"taskId":"<uuid>","message":"正在切分 Markdown Section..."}
  \n\n
  ```

#### Event Type B: `IndexCompleted`
- **Trigger:** Worker completes indexing, saves DB, caches in Redis, releases lock.
- **Payload format:**
  ```text
  event: IndexCompleted
  data: {"taskId":"<uuid>","message":"您的知識庫已編譯完成！","metadata":{"sectionsCompiled":42,"filesProcessed":5}}
  \n\n
  ```

#### Event Type C: `IndexFailed`
- **Trigger:** Worker encounters a fatal error during compilation.
- **Payload format:**
  ```text
  event: IndexFailed
  data: {"taskId":"<uuid>","message":"知識庫編譯失敗，請稍後重試。","errorCode":"LOCK_TIMEOUT"}
  \n\n
  ```

## 3. Chat Channel (POST /api/chat)

### Channel Lifecycle
- **Establishment:** Triggered by user query.
- **Stream Content:** Token chunks are streamed immediately as they are generated by the LLM.
- **Termination:** Unlike the notification channel, the Chat Channel is **short-lived**. Once the final chunk is sent, the server **MUST actively close the connection** to free resources.

### Stream Frames Sequence

The chat channel does not use named `event:` fields; it streams standard unnamed `data:` frames containing serialized JSON chunks:

1. **Source Citation Frame (Sent first):**
   Before the LLM starts generating tokens, the system performs BM25 retrieval and fetches top-K content. It sends the citation list as the first frame:
   ```text
   data: {"text":"","isFinal":false,"sources":[{"sectionId":"tenant-01#refund.md#timeline","fileName":"refund.md","heading":"Timeline","score":1.85}]}
   \n\n
   ```

2. **Token Generation Frames (Sent sequentially):**
   As the LLM produces tokens, they are pushed frame-by-frame:
   ```text
   data: {"text":"您","isFinal":false,"sources":null}
   \n\n
   data: {"text":"需要","isFinal":false,"sources":null}
   \n\n
   ```

3. **Terminal Frame (Sent last):**
   When generation completes, the final frame signals the end. This frame has `isFinal: true` and contains the complete sources array again for fallback:
   ```text
   data: {"text":"","isFinal":true,"sources":[{"sectionId":"tenant-01#refund.md#timeline","fileName":"refund.md","heading":"Timeline","score":1.85}]}
   \n\n
   ```
   *Immediately following this frame, the server closes the HTTP write stream.*

## 4. Frontend Client Implementation Blueprint

Example JavaScript snippet for parsing the chat stream:

```javascript
const response = await fetch('/api/chat', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-User-Id': 'tenant-01'
  },
  body: JSON.stringify({ query: 'Refund timeline?' })
});

const reader = response.body.getReader();
const decoder = new TextDecoder();
let buffer = '';

while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  
  buffer += decoder.decode(value, { stream: true });
  const lines = buffer.split('\n');
  
  // Save the last incomplete line back to the buffer
  buffer = lines.pop(); 
  
  for (const line of lines) {
    if (line.startsWith('data: ')) {
      const jsonStr = line.substring(6).trim();
      const chunk = JSON.parse(jsonStr);
      
      if (chunk.sources && chunk.sources.length > 0) {
        renderSources(chunk.sources);
      }
      if (chunk.text) {
        appendChatText(chunk.text);
      }
      if (chunk.isFinal) {
        console.log("Stream completed. Closing connection.");
        reader.releaseLock();
        return;
      }
    }
  }
}
```
